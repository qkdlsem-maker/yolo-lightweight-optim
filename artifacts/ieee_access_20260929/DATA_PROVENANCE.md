# Dataset provenance audit

The actual training and validation data are an existing external YOLO-format conversion. The researcher could not recall the original download source. On 2026-09-29, an independent trace identified the public Kaggle package https://www.kaggle.com/datasets/a7madmostafa/bdd100k-yolo (API current version 4, last updated 2025-10-30). Its data.yaml, the lexicographically first train/val/test label files, and the first test image are byte-identical to the corresponding local files (SHA-256 hashes in followup/kaggle_sample_hashes.json). This is strong evidence for the distribution source, not an exhaustive archive comparison or authentication of annotation generation. The package description lists the same ten classes but does not explain the test-label generation process. Its displayed CC BY-SA 4.0 designation must not be assumed to replace the original BDD100K terms.

The local train/val/test directories contain 70,000/10,000/20,000 images and corresponding nonempty label files. The 20,000 test labels are of unverified origin and are not used for official benchmark claims. The BDD100K maintainers describe withheld test labels and evaluation-server access: https://github.com/bdd100k/bdd100k/discussions/52 .

SHA-256 checks over all 100,000 encoded images found no exact train/validation duplicates. Training contains 69,999 distinct image files; validation contains 9,998. One encoded image is shared between train and test. No identical label files were shared across splits. These checks do not rule out visually similar images or video-level leakage and do not authenticate annotations. Raw summary: `followup/data_hash_audit.json`.

The repository's official-JSON converter previously used a class order inconsistent with `configs/bdd100k.yaml`. The corrected converter now matches that configuration; a category-name regression test checks this. It does not rewrite the existing dataset or claim to have produced the archived labels. Further confirmation or reconstruction from official annotations is required before submission. The ongoing continuation uses the unchanged existing train/validation files so that the arms remain comparable; its scores remain conditional on this conversion.
